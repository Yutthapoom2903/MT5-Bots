# MT5-Bots

บอทเทรด XAUUSD (ทองคำ) บน MetaTrader 5 ใช้ MA20/MA50 crossover เป็นจุดชนวน
แล้วกรองด้วยหลาย timeframe ก่อนตัดสินใจเอง

**ทุกอย่างสั่งผ่านคำสั่งเดียว: `python run.py`**

---

## สิ่งที่ต้องมีก่อน

1. **Windows** — แพ็กเกจ `MetaTrader5` ของ Python ทำงานบน Windows เท่านั้น
   รันจาก WSL หรือ Linux ไม่ได้ (ยกเว้นคำสั่ง `backtest` กับ `test`)
2. **MT5 terminal เปิดอยู่และล็อกอินแล้ว** บอทคุยกับ terminal ที่เปิดอยู่ ไม่ได้ล็อกอินเอง
3. **เปิด Algo Trading ใน MT5** ปุ่มบนแถบเครื่องมือ ถ้าไม่เปิดคำสั่งจะถูกปฏิเสธ
4. Python 3.9 ขึ้นไป

## ติดตั้ง

```powershell
pip install -r requirements.txt
```

สร้างไฟล์ `.env` (คัดลอกจาก `.env.example`) ถ้าต้องการแจ้งเตือนผ่าน Telegram —
ไม่ใส่ก็ได้ บอททำงานปกติ แค่ไม่ส่งข้อความ

```
TELEGRAM_TOKEN=โทเคนจาก @BotFather
TELEGRAM_CHAT_ID=chat id ของคุณ
```

## เริ่มใช้งาน — ทำตามลำดับนี้

### 1. หาชื่อ Symbol ที่ broker ใช้จริง

```powershell
python run.py symbols
```

broker แต่ละเจ้าตั้งชื่อทองไม่เหมือนกัน (`XAUUSD`, `XAUUSD.m`, `GOLD`, `XAUUSDm`)
ถ้าที่ขึ้นมาไม่ใช่ `XAUUSD` ให้แก้ `SYMBOL` ที่หัวไฟล์ `runner.py`

### 2. ตรวจความพร้อม

```powershell
python run.py check
```

บอกการเชื่อมต่อ ข้อมูลบัญชี เงื่อนไขของ Symbol และ **คำนวณให้ดูว่าทุนที่มีพอกับ
ความเสี่ยงที่ตั้งไว้หรือไม่** อ่านหัวข้อ "เรื่องทุน" ด้านล่างประกอบ

### 3. ดูว่าตอนนี้บอทคิดยังไง

```powershell
python run.py signal
```

พิมพ์คำตัดสินครั้งเดียวพร้อมเหตุผลทุกข้อ ทั้งที่ผ่านและไม่ผ่าน เช่น

```
สัญญาณ: BUY
เข้าไม้: ไม่

  [ผ่าน  ] สัญญาณตัดกัน M15: MA20/MA50 ให้ BUY
  [ไม่ผ่าน] เทรนด์ H1: H1 = DOWNTREND, ต้องการ UPTREND
  [ผ่าน  ] ความแรงเทรนด์ ADX: ADX = 24.1, ต้อง >= 20
  [ผ่าน  ] RSI ไม่ยืดเกิน: RSI = 58.0, BUY ต้อง <= 70
  [ผ่าน  ] M5 ไม่สวนทาง: M5 = SIDEWAY, ห้ามเป็น DOWNTREND
  [ผ่าน  ] Spread: 26.0 points, ต้อง <= 50
```

### 4. เฝ้าดูก่อน อย่าเพิ่งเทรด

```powershell
python run.py
```

คำสั่งเปล่าๆ = ตรวจความพร้อม แล้วเข้าลูปเฝ้าดู **ไม่ส่งคำสั่งซื้อขายใดๆ**
บันทึกทุกแท่งที่ปิดลง CSV พร้อมคำตัดสินและเหตุผล ปล่อยไว้อย่างน้อย 1-2 สัปดาห์
แล้วค่อยดูว่ากลยุทธ์นี้ให้ผลยังไงก่อนปล่อยให้เทรดจริง

### 5. ให้เทรดจริง (Demo ก่อนเสมอ)

```powershell
python run.py trade
```

บอทจะปฏิเสธไม่สตาร์ทถ้าเจอบัญชีจริง เว้นแต่แก้ `ALLOW_LIVE_ACCOUNT = True`
ใน `runner.py` ด้วยตัวเอง — ตั้งใจให้ต้องแก้เอง จะได้ไม่เผลอ

หยุดด้วย `Ctrl+C` ทุกโหมด

## บอทตัดสินใจยังไง

ไม่ได้ดู timeframe เดียว แต่ละอันมีหน้าที่ต่างกัน:

| Timeframe | หน้าที่ |
|---|---|
| **H1** | กำหนดทิศ — เทรดตามเทรนด์ใหญ่เท่านั้น ไม่สวน |
| **M15** | จุดชนวน — MA20 ตัด MA50 คือจังหวะเข้า |
| **M5** | ยืนยัน — โมเมนตัมสั้นต้องไม่สวนกับไม้ที่จะเปิด |

แล้วกรองอีกชั้นก่อนเข้าจริง:

| ตัวกรอง | เหตุผล |
|---|---|
| ADX ≥ 20 | ตลาด sideway คือที่ที่ MA crossover ให้สัญญาณหลอกถี่สุด |
| RSI 30–70 | ไม่ไล่ราคาที่ยืดไปไกลแล้ว |
| spread ≤ 50 points | spread กว้างกินกำไรตั้งแต่ยังไม่เริ่ม |
| ช่วงเวลา | ปิดไว้เป็นค่าเริ่มต้น เปิดได้ใน `strategy.py` |

ทุกตัวเปิด/ปิดแยกกันได้ที่หัวไฟล์ `strategy.py` — **ปิดทีละตัวแล้ววัดผล**
อย่าเปลี่ยนพร้อมกันหลายอย่าง จะไม่รู้ว่าตัวไหนช่วยตัวไหนทำพัง

## บอทดูแลไม้ยังไงหลังเปิดแล้ว

เปิดไม้แล้วไม่ได้ทิ้ง — ทุกรอบ 30 วินาที (ไม่ใช่แค่ตอนแท่งปิด) บอทจะดู SL ให้

| กลไก | ทำงานเมื่อ | ทำอะไร |
|---|---|---|
| **ย้ายมาเสมอทุน** | กำไรถึง 1R | เลื่อน SL มาที่ราคาเข้า +0.1R กันค่า spread |
| **ไล่ stop** | กำไรถึง 1.5R | ลาก SL ตามห่างจากราคา 2×ATR |

`1R` = ระยะ SL ตอนเปิดไม้ ถ้าเสี่ยง $16 แล้วกำไรถึง $16 คือ 1R

**SL ขยับไปทางกำไรได้อย่างเดียว ถอยหลังไม่ได้เด็ดขาด** ถ้าถอยได้เมื่อไหร่ การไล่ stop
จะกลายเป็นการขยายความเสี่ยงแทน

ปิด/ปรับได้ที่ `USE_BREAKEVEN`, `USE_TRAILING`, `BREAKEVEN_AT_R`, `TRAIL_START_R`,
`TRAIL_ATR_MULT` ใน `runner.py`

## ตัวตัดวงจร — บอทหยุดเองเมื่อวันไม่เข้าทาง

รันทิ้งไว้ที่บ้านโดยไม่มีคนเฝ้า สิ่งที่กลัวที่สุดคือวันที่บอทแพ้รัวแล้วไม่มีใครปิด

| เพดาน | ค่าเริ่มต้น | ผล |
|---|---|---|
| ขาดทุนต่อวัน | 3% ของทุนต้นวัน | หยุดเข้าไม้ใหม่ทั้งวัน |
| จำนวนไม้ต่อวัน | 5 ไม้ | หยุดเข้าไม้ใหม่ทั้งวัน |
| แพ้ติดกัน | 3 ไม้ | หยุดเข้าไม้ใหม่ทั้งวัน |

หยุดแค่**การเข้าไม้ใหม่** ไม้ที่ถืออยู่ยังถูกดูแล SL ต่อตามปกติ

ตัวเลขอ่านจากประวัติจริงใน MT5 ทุกครั้ง ไม่ได้นับในหน่วยความจำ — restart บอทกลางวัน
เพดานก็ยังนับต่อถูก ไม่รีเซ็ต

พอขึ้นวันใหม่ บอทรีเซ็ตเพดานและส่งสรุปของเมื่อวานเข้า Telegram

แก้ที่ `MAX_DAILY_LOSS_PERCENT`, `MAX_TRADES_PER_DAY`, `MAX_CONSECUTIVE_LOSSES`

## ความทนทานเวลารันทิ้งไว้

- **หลุดการเชื่อมต่อ** — ถ้า MT5 terminal ปิดหรือเน็ตหลุด บอทตรวจเจอแล้วเชื่อมใหม่เอง
  ไม่ตายเงียบ
- **ตลาดปิด** — เสาร์อาทิตย์บอทไม่ poll ถี่ ถอยไปเช็คทุก 5 นาทีแทน
- **restart กลางแท่ง** — `bot_state.json` จำแท่งล่าสุดที่ประมวลผลแล้ว ไม่ยิงซ้ำ
- **restart ระหว่างถือไม้** — จำ 1R ของแต่ละ ticket ไว้ ถ้าหาย ประมาณจาก SL ปัจจุบันแทน
- **error ที่ไม่คาดคิด** — เขียน traceback ลง `bot.log` แล้วแจ้ง Telegram ก่อนหยุด

## เรื่องทุน — อ่านให้จบก่อนใช้เงินจริง

XAUUSD ไม้เล็กสุดคือ **0.01 lot = ทอง 1 ออนซ์** เล็กกว่านี้ไม่ได้

SL ของบอทคือ `ATR × 1.5` ซึ่งตอนนี้อยู่ราว **$16 ต่อไม้** แปลว่าไม้ที่เล็กที่สุด
ที่เปิดได้ก็เสี่ยง $16 แล้ว กดต่ำกว่านี้ไม่ได้

| ทุน | เสี่ยงต่อไม้ | สภาพ |
|---|---|---|
| $500 | 3.3% | อันตราย แพ้ 10 ไม้ = พอร์ตหาย 1 ใน 3 |
| **$1,000** | **1.6%** | ตึง แต่พอไปได้ |
| $2,000 | 0.8% | เหมาะสม |
| $3,300 | 0.5% | ตรงตามค่าเริ่มต้นเดิม |

**แนะนำอย่างต่ำ $2,000** ถ้าจะใช้เงินจริง

ค่าเริ่มต้นคือ `RISK_PERCENT = 1.0` ใน `runner.py`

**บน Demo บอทจะเทรดต่อโดยเตือนใน log** ว่าเสี่ยงเกินงบไปเท่าไร เพราะจุดประสงค์ของ Demo
คือได้เห็นบอททำงานจริง **บนบัญชีจริงบอทจะปฏิเสธไม่เข้าไม้** แล้วบอกเหตุผล ทางเลือกคือ

- เพิ่มทุนเป็น $1,700 ขึ้นไป (ทางที่ถูกต้อง)
- ตั้ง `RISK_PERCENT = 2.0` — ยอมรับว่าเสี่ยงสูงขึ้น
- ลด `SL_ATR_MULT` — แต่ SL แคบลงแปลว่าโดน stop ง่ายขึ้น ระวัง
- ตั้ง `ALLOW_RISK_OVER_BUDGET = True` — ให้เทรดทั้งที่รู้ว่าเกินงบ

บน Demo จะเลือกอะไรก็ได้ ไม่มีอะไรเสียหาย แต่พอขึ้นเงินจริงต้องคิดให้จบ

## ข้อควรรู้

- **ยังไม่เคยทดสอบกับ MT5 จริง** โค้ดผ่านเทส logic แต่พฤติกรรมของ broker
  (retcode, ระยะ stop ขั้นต่ำ, filling mode) ต้องเจอของจริงถึงรู้ **รัน Demo ก่อน**
- บอทตัดสินใจจากแท่งที่**ปิดแล้ว**เท่านั้น จึงเข้าช้ากว่าแท่งปัจจุบันเสมอ — ตั้งใจให้เป็นแบบนั้น
  ไม่งั้นสัญญาณจะเปลี่ยนไปมากลางแท่ง
- MA crossover เป็นกลยุทธ์ตามเทรนด์ ในตลาด sideway จะแพ้เป็นชุด ตัวกรอง ADX
  ช่วยได้ระดับหนึ่ง แต่ไม่ได้แก้หมด
- การไล่ stop ทำให้ไม้ที่กำไรถูกปิดเร็วขึ้น กำไรต่อไม้จะลดลงแลกกับการรักษากำไรได้แน่นอนขึ้น
  ถ้าอยากปล่อยให้วิ่งยาว ให้เพิ่ม `TRAIL_ATR_MULT` หรือปิด `USE_TRAILING`
- ผลบน Demo ไม่เท่ากับผลจริง เพราะไม่มี slippage และการ requote แบบบัญชีจริง
