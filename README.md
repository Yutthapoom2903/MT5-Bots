# MT5-Bots

บอทเทรด XAUUSD (ทองคำ) บน MetaTrader 5 — MA20/MA50 crossover บน M15 เป็นจุดชนวน
H1 กำหนดทิศ M5 ยืนยัน ADX/RSI/spread ยับยั้ง บันทึกทุกแท่งพร้อมเหตุผลที่ตัดสินแบบนั้น

**ทุกอย่างสั่งผ่าน `run.py` คำสั่งเดียว — ไม่อยากจำอะไรเลยใช้ `python run.py menu`**

---

## รอบการใช้งานประจำวัน

บอทไม่ได้รัน 24/7 — รันเป็น**รอบ** ตอนถึงบ้านจนตื่น คืนละรอบ รายงานทุกตัวออกแบบตามนี้

### ที่บ้าน (Windows + MT5 เปิดอยู่) — ตอนถึงบ้าน

```powershell
git pull
python run.py menu
```

เมนูบอกเองว่ามีอะไรให้ทำ และบอกด้วยว่าตอนนี้เก็บมากี่แท่งแล้ว เคยส่งคำสั่งจริงหรือยัง
ข้อที่ต้องใช้ MT5 จะขึ้น `(ต้องมี MT5)` และกดไม่ได้บนเครื่องที่ไม่มี

```
  ตอนถึงบ้าน
    1) เทรดบน Demo (เก็บข้อมูล + ส่งคำสั่งจริง)
    2) เฝ้าดูอย่างเดียว ไม่ส่งคำสั่ง
    3) ตรวจความพร้อม บัญชี และความเสี่ยง

  อ่านผล
    4) สรุปว่าบอททำอะไรไปบ้าง
    5) ตัวกรองแยกอะไรได้จริงไหม
    6) ให้คะแนนป้ายที่กรอกเอง
```

**กด 3 ก่อน แล้วค่อยกด 1** — 3 ยืนยันว่าเป็นบัญชี Demo จริง

พิมพ์คำสั่งเองก็ได้เหมือนกัน:

```powershell
python run.py check       # ยืนยันก่อนว่าเป็น Demo จริง
python run.py --trade     # ปล่อยรันข้ามคืน
```

**`git pull` ก่อนเสมอ** ไม่งั้นรันโค้ดเก่า คอลัมน์ในไฟล์ที่เขียนออกมาจะไม่ตรงกัน

**`check` ดูสามบรรทัดนี้ก่อนไปต่อ**

| บรรทัด | ต้องเห็น |
|---|---|
| `บัญชี: xxx (Demo)` | ต้องเป็น **Demo** ขึ้น "บัญชีจริง" อย่ารัน `--trade` |
| `เวลาเซิร์ฟเวอร์ broker: GMT+?` | จดไว้ ใช้ตีความชั่วโมงในรายงาน |
| `ทุนพอ — ขนาดไม้ที่จะใช้ตอนนี้: x lot` | ขึ้น "ทุนไม่พอ" = บอทข้ามทุกสัญญาณ ไม่มีไม้ให้ดู |

`--trade` จบในคำสั่งเดียว: หา Symbol → ตรวจความพร้อม → วัดตัวกรองจากข้อมูลที่เก็บมา →
จำลองย้อนหลัง → กวาดค่า → เฝ้าดูตลาดสดและส่งคำสั่ง

ถ้าเป็นบัญชีจริง `--trade` หยุดเองทันทีพร้อมบอกเหตุผล (`ALLOW_LIVE_ACCOUNT = False`)

**ยังไม่อยากให้ส่งคำสั่ง** ใช้ `python run.py` เฉยๆ เฝ้าดูอย่างเดียว — แต่แบบนั้น retcode,
filling mode และระยะ stop ขั้นต่ำของ broker จะไม่เคยถูกพิสูจน์สักที

อยากเข้าเฝ้าดูเลยไม่ต้องรอจำลอง: เติม `--skip-backtest`

### สองอย่างที่ต้องรู้เรื่องข้อมูลที่ได้

**1. ขาดกลางรอบเท่านั้นที่เป็นปัญหา** — `run.py report` หัวข้อ **รอบที่รัน** แยกให้แล้วว่า
อันไหนคือ "ไม่ได้รัน" (ไม่นับ) อันไหนคือ "ขาดกลางรอบ" (เน็ตหลุด เครื่อง sleep MT5 ปิดเอง)

```
--- รอบที่รัน ---
รันไป 2 รอบ เก็บได้ 39 แท่ง
  2026-09-09 17:30:00 -> 2026-09-10 04:45:00  38 แท่ง (11.2 ชม.)  ขาดกลางรอบ 8 แท่ง
ขาดกลางรอบรวม 8 แท่ง จาก 47 ที่ควรมีในรอบที่รัน (83%) — เฉพาะพวกนี้ที่ควรตามหาสาเหตุ
```

**2. ข้อมูลเป็นของ session เดียว** รันคืนละรอบแปลว่าเก็บได้ราว 11 จาก 24 ชั่วโมง
สถิติทุกตัวเป็นของช่วงนั้น ไม่ใช่ของตลาดทั้งวัน — `report` กับ `outcomes` พิมพ์ชั่วโมงที่ครอบคลุมไว้ให้

`python run.py check` พิมพ์ GMT offset ของ broker ตอนเริ่ม เอาไปเทียบว่ารอบที่รันตรงกับ
session ไหน ถ้า broker เป็น GMT+3 ชั่วโมง 17–04 คือ London บ่าย + New York เต็มรอบ
ซึ่งเป็นช่วงที่ทองมีสภาพคล่องดีที่สุดพอดี

## ติดตั้ง

**Windows** (เครื่องที่รันบอทจริง)

```powershell
pip install -r requirements.txt
```

ต้องมี MT5 terminal **เปิดอยู่ ล็อกอินแล้ว และเปิด Algo Trading** บอทไม่ได้ล็อกอินเอง

### สั่งผ่าน SSH หรือ scheduled task

แพ็กเกจ `MetaTrader5` หา terminal เองไม่เจอเมื่อสั่งจาก session ที่ไม่มีหน้าจอ
ล้มด้วย `[-10003] IPC initialize failed, MetaTrader 5 x64 not found` ทั้งที่ terminal
เปิดค้างอยู่ใน session อื่น บอกทางไปให้ตรงๆ ใน `.env`

```
MT5_TERMINAL_PATH=C:\Program Files\MetaTrader 5\terminal64.exe
```

หา path จริงของตัวที่รันอยู่ด้วย

```powershell
powershell -c "Get-Process terminal64 | Select-Object -ExpandProperty Path"
```

ตั้งแล้ว SSH สั่งงาน terminal ที่เปิดค้างอยู่ในหน้าจอได้ตามปกติ — เปิดและล็อกอิน MT5
ครั้งแรกยังต้องทำผ่านหน้าจอ (RDP หรือหน้าเครื่อง) เพราะเป็น GUI
**disconnect RDP ได้ แต่อย่า sign out** — sign out คือปิด terminal ไปด้วย

**WSL/Linux** (เครื่องที่อ่านผล) — `MetaTrader5` ไม่มีตัว Linux ต้องลงเฉพาะที่เหลือ

```bash
python3 -m venv .venv && .venv/bin/pip install pandas requests python-dotenv
.venv/bin/python run.py test
```

## ลำดับการพิสูจน์ก่อนใช้เงินจริง

`python run.py` เป็นโหมด**เฝ้าดู ไม่ส่งคำสั่ง** เก็บข้อมูลได้อย่างเดียว จะพิสูจน์อะไรไม่ได้เลย
ถ้าไม่เคยมีคำสั่งวิ่งจริงสักครั้ง สามคำถามข้างล่างเป็นคนละคำถาม ใช้เครื่องมือคนละตัว
และใช้เวลาต่างกันเป็นร้อยเท่า

| คำถาม | เครื่องมือ | ใช้เวลา |
|---|---|---|
| กลยุทธ์เคยมี edge ไหม | `run.py backtest` + `sweep` (ประวัติหลายปี) | หลักนาที |
| ตัวกรองแยกอะไรได้จริงไหม | `run.py outcomes` (ป้ายทุกแท่ง) | ไม่กี่วัน |
| ส่งคำสั่งกับ broker ได้จริงไหม | **`run.py --trade` บน Demo** | ไม่กี่คืน |
| สถิติผลไม้พอจะเชื่อได้ | ต้องมีไม้ราว 100 ไม้ | **~1 ปี** |

**อย่ารอไม้ครบ 100 ไม้บน Demo ก่อนขึ้นเงินจริง** — ที่อัตราปัจจุบัน (crossover ~1 ครั้ง/คืน
ผ่านตัวกรองเป็นส่วนน้อย) กว่าจะครบใช้เวลาราวหนึ่งปี Demo มีไว้พิสูจน์ **กลไก** ไม่ใช่สถิติ:
retcode, filling mode, ระยะ stop ขั้นต่ำ, การปัด lot, slippage ของจริง — ของพวกนี้พิสูจน์จบ
ในไม่กี่คืน ส่วน **edge** พิสูจน์ด้วย backtest บนประวัติหลายปี ไม่ใช่ด้วยการรอ

```powershell
python run.py --trade    # บน Demo เท่านั้น
```

`ALLOW_LIVE_ACCOUNT = False` กันไว้แล้ว — เจอบัญชีจริงจะหยุดทันทีพร้อมบอกเหตุผล

`run.py report` เตือนให้เองถ้า `trade_log.csv` ยังว่าง

### สองหลักการเวลาเก็บข้อมูล

**1. อย่าจูนค่าจากข้อมูลที่เก็บมาเอง** ยิ่งลองหลายเกณฑ์บนชุดเดียว ยิ่งเจอ "ค่าที่ดี" ที่เป็นแค่
ความบังเอิญ (multiple testing) `sweep` ถึงรายงานทั้งย่านแทนที่จะบอกผู้ชนะ และ `outcomes`
ถึงเรียกส่วนต่างที่ n น้อยว่าเสียงรบกวน — เก็บข้อมูลไว้ **วัด** อย่าเอาไว้ **จูน**

**2. เวลาในไฟล์เป็นเวลาเซิร์ฟเวอร์ broker และมันขยับตาม DST** ทุกแถวเลยบันทึก
`broker_gmt_offset` ไว้ด้วย ถ้า broker ขยับกลางทาง `report` จะเตือนว่าชั่วโมงในไฟล์
ไม่ใช่เวลาเดียวกันทุกแถว (แถวที่เก็บก่อน 2026-09-10 ยังไม่มีคอลัมน์นี้)

## เรื่องทุน — อ่านก่อนใช้เงินจริง

XAUUSD ไม้เล็กสุดคือ **0.01 lot** เล็กกว่านี้ไม่ได้ SL ของบอทคือ `ATR × 1.5` ราว **$16 ต่อไม้**
แปลว่าไม้ที่เล็กที่สุดที่เปิดได้ก็เสี่ยง $16 แล้ว กดต่ำกว่านี้ไม่ได้

| ทุน | เสี่ยงต่อไม้ | สภาพ |
|---|---|---|
| $500 | 3.3% | อันตราย |
| $1,000 | 1.6% | ตึง |
| **$2,000** | **0.8%** | **แนะนำอย่างต่ำ** |
| $3,300 | 0.5% | สบาย |

Demo เสี่ยงเกินงบแล้วเทรดต่อพร้อมเตือนใน log **บัญชีจริงปฏิเสธไม่เข้าไม้**
`python run.py check` คำนวณเลขนี้กับบัญชีจริงให้ดู เป็นทางที่เร็วที่สุดในการตอบว่า
"ทำไมบอทไม่เข้าไม้สักที"

ค่าที่แก้ได้ใน `runner.py`: `RISK_PERCENT` (1.0), `SL_ATR_MULT` (1.5), `TP_ATR_MULT` (3.0),
`MAX_DAILY_LOSS_PERCENT` (3.0), `MAX_TRADES_PER_DAY` (5), `MAX_CONSECUTIVE_LOSSES` (3)

## บอทตัดสินใจยังไง

| Timeframe | หน้าที่ |
|---|---|
| H1 | กำหนดทิศ — เทรดตามเทรนด์ใหญ่เท่านั้น |
| M15 | จุดชนวน — MA20 ตัด MA50 |
| M5 | ยืนยัน — โมเมนตัมสั้นต้องไม่สวน |
| ADX / RSI / spread | ยับยั้ง — ตลาดไม่มีเทรนด์ หรือราคายืดไปแล้ว ให้ข้าม |

ใช้เฉพาะ**แท่งที่ปิดแล้ว** เข้าช้ากว่าราคาปัจจุบันเสมอ — ตั้งใจ ไม่งั้นสัญญาณพลิกกลางแท่ง

ตัวกรองเปิด/ปิดได้ทีละตัวใน `strategy.py` (`USE_H1_TREND_FILTER`, `USE_ADX_FILTER`,
`USE_RSI_FILTER`, `USE_M5_CONFIRM`) พร้อมเกณฑ์ `ADX_MIN` (20), `MAX_SPREAD_POINTS` (50)

หลังเปิดไม้: เลื่อน SL ไป breakeven ที่ 1R แล้วไล่ตาม ATR ที่ 1.5R
**SL ขยับไปทางกำไรอย่างเดียว ไม่มีทางถอยกลับ**

```powershell
python run.py notify --dry    # พิมพ์ตัวอย่างลงจอ ไม่ต้องมี token
python run.py notify --check  # ข้อความไม่มา ใช้อันนี้หาว่าขาดตรงไหน
```

- **บอทเริ่มบทสนทนาเองไม่ได้** ต้องกด Start ในแชทบอทก่อนหนึ่งครั้ง ไม่งั้น Telegram ตอบ 403 ตลอด
- **กรอกลง `.env` เท่านั้น** `.env.example` เป็นแบบฟอร์ม โปรแกรมไม่อ่าน และไฟล์นั้นติดตาม git อยู่ —
  กรอก token ลงไปคือเตรียม commit ความลับขึ้น repo (`--check` ดักให้แล้ว)

8 หมวด เปิด/ปิดแยกกันได้ใน `notify.py`: `lifecycle` `market` `signal` `entry` `manage`
`exit` `risk` `summary` — `SEND_HOLD` เปิดมาโดยตั้งใจ ข้อความทุกแท่งคือหลักฐานถูกที่สุดว่าท่อไม่ตัน

## ข้อควรรู้

- **ยังไม่เคยทดสอบกับ MT5 จริง** logic ผ่านเทสหมด แต่พฤติกรรม broker (retcode,
  ระยะ stop ขั้นต่ำ, filling mode) ต้องเจอของจริงถึงรู้ — **Demo ก่อน**
- MA crossover เป็นกลยุทธ์ตามเทรนด์ ตลาด sideway จะแพ้เป็นชุด ADX ช่วยได้ระดับหนึ่ง ไม่ได้แก้หมด
- ตัวเลขจาก `outcomes` เป็นการเคลื่อนไหวของตลาดดิบๆ **ไม่ใช่กำไรของไม้** ไม่มี spread
  ไม่มีเลื่อน stop ไม่มี TP — จะตัดสินว่ากลยุทธ์ทำเงินได้ไหมต้องใช้ `run.py backtest`
- ผล Demo ไม่เท่าผลจริง ไม่มี slippage และ requote แบบบัญชีจริง
- รองรับ symbol เดียวเท่านั้น — ทุก risk limit, ตัวตัดวงจร และ state file ออกแบบมาแบบนั้น
